## 👨‍💻 Sobre mim

Sou desenvolvedor Front-End e estudante de Ciência da Computação, PB. Gosto de pensar no Front-End como engenharia de produto: não é só sobre replicar um layout no Figma, é sobre gerenciar estado de forma previsível, pensar na arquitetura do código e garantir que a interface seja rápida e acessível.

Meu ecossistema principal é o **React**. No dia a dia, fujo de "soluções mágicas" e prefiro entender o que está acontecendo por baixo dos panos. Estudo e desenvolvo ferramentas SaaS no meu tempo livre para testar na prática conceitos de separação de responsabilidades (Lógica vs UI) e arquitetura de software.

## 📦 Projetos em Destaque

Trato meus repositórios pessoais como produtos reais. Aqui estão os que mais refletem meu modo de programar:

### 🏗️ [Modulor](https://github.com/joaoemanuels/Modulor) — Drag & Drop Form Builder ( em desenvolvimento )
Um SaaS para construção de formulários que foge da mecânica padrão. 
- **O desafio técnico:** Lidar com drag and drop nativo do HTML5 é péssimo para acessibilidade. Implementei o `@dnd-kit` e usei o `Zustand` para gerenciar a árvore de nós do formulário sem causar re-renders desnecessários a cada movimento do mouse na tela. 
- **Stack:** React 18, Vite, Zustand, dnd-kit, CSS Variables.

### 🧠 [Decisio](https://github.com/joaoemanuels/decisio) — Motor de Decisão para Devs
Um sistema que consome regras em JSON e gera uma árvore de decisão dinâmica para recomendar stacks tecnológicas.
- **O desafio técnico:** Manter a regra de negócio isolada. Toda a lógica de pontuação com pesos vive separada dos componentes React. A UI apenas reflete o estado calculado pelo motor de forma transparente.
- **Stack:** React Router v6, Vite, JSON Engine, jsPDF.

### 📅 AgendaPro — Sistema de Gestão
Aplicação web estruturada com processos de CI/CD (integração entre GitHub, Vercel e Render), focada em manter um fluxo de trabalho profissional separando branches de desenvolvimento e produção.
